# 重点标注的泛化评测

不要把标注覆盖率当作质量分数。更稀疏可能意味着读起来清楚，也可能意味着漏掉否定、条件或并列要求。

## 数据如何使用

- 原来的 13 条浏览器缓存样本已经反复用于调试，只能算回归集，不能证明泛化能力；不将这些私人缓存写进仓库。
- `generalization.json` 是独立编写的合成文本，包含中英文叙事、说明、研究结论、通知、操作要求、数字比较和短标题。8 条 development 用于开发，12 条 heldout 在本轮规则固定后才运行。
- `focus` 和 `guard` 是人工阅读参考，不是唯一正确的粗体边界；不发给模型。不要求每个正确细节都标亮，但已标结论不能丢失决定其含义的限制。
- 看过 heldout 输出后，不能再根据它修提示词并把同一数据称为盲测。若把它用于下一轮开发，需另建新的、预先冻结的保留集。
- 这仍是小规模合成评测，未覆盖所有文体，也不是独立人工标注的大样本。后续应加入未用于调优、经用户授权的真实文章。

## 怎么运行

在环境中设置 `DEEPSEEK_API_KEY`，运行：

```sh
node scripts/evaluate-key-info.mjs --split development --out /tmp/key-info-development.json
node scripts/evaluate-key-info.mjs --split heldout --out /tmp/key-info-heldout.json
```

可用 `--baseline /path/to/frozen-modules` 对比旧版本；目录需包含 `background/key-info.js` 与 `shared/key-info.js`，并支持 ES module。评测只访问配置的模型接口，不读取浏览器存储或查找密钥。已有结果文件不会被覆盖。

同一轮中，完全相同的模型请求会复用结果，避免将两次采样差异误算为代码变化。报告记录模型名、数据/提示词/策略代码摘要、实际请求数、token 用量、逐条输出、覆盖率和格式校验结果。合成模型文本保存在指定的结果文件，密钥不保存。

## 判断顺序

1. 原文、顺序、标点和空白是否完整保留。
2. 已突出内容的否定、条件、例外、数值对象和并列要求是否完整，是否会误导扫读者。
3. 重点是否体现本段主要信息；背景、示例、API 名称或重复内容是否压过主旨。
4. 密度、跨度和阅读层次是否合适。信息密集的必要步骤可以比叙事更密，短标题可以不标；不统一压到固定百分比。
5. 额外请求、耗时与缓存效果。是否为不明确的句式白白增加修正调用。

程序校验通过只代表格式与保真，不代表语义准确。

## 2026-09-29 本轮结果

本轮只收紧自动补齐的触发条件，没有继续改写模型提示词，也没有为单个例子增加特例：去掉单字起始与泛用英文 For，并要求时间条件有明确标点边界。

- 本地反例中，旧策略会把“若有所思”“当代建筑”“要点……”和“For example”当成条件，额外扩大标注；新策略停止这些不确定扩展。
- 开发集：8/8 保真校验通过。保留集：12/12 保真校验通过。
- 保留集的 2 条叙事案例改变了结果：不再自动突出“当年河岸边只有几间木屋”和“For generations”。其余 10 条与固定基线输出相同，包含条件/否定、步骤、数值和短标题。
- 人工阅读仍发现人数上限样本没有突出“儿童也计入”的限制；本轮只记录，没有依据保留集输出再调规则。不要把 12/12 保真误报为 100% 语义准确率。
- 共实际调用 27 次、44,374 tokens。第一轮响应在基线和候选之间共享；浏览器缓存没有被修改。

取舍：对于没有标点分隔、只有模糊起始词的真实条件，程序不再强行补齐，主要由模型选择。宁可承认规则能力边界，也不要为了旧样本的分数扩大到不可靠的自动改动。

## 第一阶段收尾（2026-09-29）

最后一轮只修复句子边界问题，提示词和密度阈值保持不变。原来的条件补齐扫描不识别英文句号，会因后一句出现重点而错误突出前一句条件，也会漏掉英文段落后续句子的条件。现在使用原生句子分段，按原文位置补齐；分段时暂时折叠换行，输出仍保留原有空白。小数和字段名内部的点不作为普通句号拆开。

- `npm test`：88 项通过，新增跨句误补齐、后续句条件、中英文及 UTF-16 位置、换行、小数与字段名的回归。
- `node scripts/check-full-translation.mjs`：隔离 Chrome 回归全部通过，覆盖渐进显示、缓存复用、并发设置、样式、失败回退和取消后的迟到结果。模型响应全部模拟，本轮没有付费模型调用。
- 没有重跑或继续针对已看过的保留集调参；上述结果证明实现回归通过，不代表语义质量得分提高或准确率达到 100%。

第一阶段到此结束。已知边界仍包括：模型可能漏掉并列限制，密度修正不能保证每段的最佳阅读层次；自动补齐仅覆盖明确句首关系，原生句子分段也不是完整语法分析。后续先正常使用，积累新文章中影响理解的重复问题，再决定是否启动下一阶段；不以少数个例新增词语特例，也不追求固定覆盖率。

加载方式：在扩展管理页重新加载扩展，再刷新阅读页面。已有模型批次缓存仍可复用，缓存响应会经过新的边界处理；本轮无需主动清空所有缓存。
