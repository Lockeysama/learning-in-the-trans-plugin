01

先给方向

Littp v1 是 Chrome 扩展：把中英文网页变成刚够看懂的英文。

当前结论

v1：首次设置采集基础信息并做短句互译，由 AI 生成种子熟词表；学习视图是连续英文，生词或短语后紧跟全角括号中文。翻译释义只覆盖被标注单位。一键回到处理前原文。

主要依据

产品方确认名称、Chrome、DeepSeek、同一英文视角、原文语义、两段正确样例，以及单靠学历和工作经历很难判断水平，需要短句互译作补充信号。

适用边界

这里还没有代码和实测。等待时长、中文页英译、种子词表误伤，都要等原型验证。成本不作约束，但首屏等待仍算体验失败。

下一步

按第 6 章分期：先骨架和初始设置，再英文页学习视图。不要并行做划词和润色。

这份文档把产品判断收成需求，把需求收成可写的技术方案和开发计划。它不是已验证的实现。

已确认的用户判断

主收益是读懂英文，不是会说。

中文页和英文页都进入同一学习视图：英文句子 + 单位（中文）。

切原文 = 不看处理后的英文，回到处理前页面。中文页样例里的中文段是原文，不是默认并排展示。

首次用基础信息加短句互译生成种子熟词表，减少前期把常见词标成生词。

仍是分析草稿或假设

Translation Agent 应是确定流水线，不是自由规划的对话 Agent。

难度只改变熟词门槛，不改写句子。

短语如何切分（如 regardless of）尚未用代码验证。

十几句互译只能校正档位，推不出完整个人词表；忘了的课标词仍可能被当成熟词。

02

最终需求

v1 只服务中文母语、目标英语的阅读增强。

当前结论

首次打开先完成初始设置。之后默认学习视图：英文不断；看不懂的词或短语后紧跟 （中文释义）。难度只决定有多少单位被标注。随时回到处理前原文。

主要依据

产品方给出的英文页和中文页样例都是这个形态。常见词被当成生词会毁掉信任。

适用边界

只覆盖网页正文阅读。不承诺口语、听力、视频、任意语种。

下一步

实现时按用户故事验收，不要把后置功能提前做进默认路径。

用户与场景

首次设置采集基础信息 + 短句互译；AI 分析后生成种子熟词表
使用者母语中文、想增强英语阅读的人
英文网页保留英文原文，只在生词/短语后插入中文释义
中文网页先译成英文，再套同一套标注；默认不并排显示中文原文
疲劳调低难度（更多词当生词、中文更多），或一键回原文

默认体验

标注单位可以是词，也可以是短语。中文用全角括号，紧跟在英文单位之后，不打断英文阅读顺序。下面两段是目标效果，实现应对齐它们。

英文页学习视图

I woke up early, made a pot of tea, and watched the rain. The sky was grey, but the air felt refreshingly cool（清凉宜人）. The rain had eased（减弱）, so I decided to go out, regardless of（不管） the weather. The streets were empty, and the world seemed oddly peaceful（出奇地平静）. Sometimes, what we need isn't a plan but a pause（停顿）.

中文页先变成英文，再套同一套标注。下面第一段是处理前原文；第二段才是学习视图。点原文，回到第一段，而不是再生成一份中文译文。

中文页：原文

周二傍晚，我关掉电脑，沿着河堤慢慢走。天色渐暗，路灯一盏盏亮起。我忽然明白，生活的意义并不总在远方，它常常藏在那些不起眼的日常里。我们需要的，也许只是驻足片刻，重新打量身边的世界。

中文页：学习视图

On Tuesday evening, I turned off my computer and walked slowly along the riverside path（河堤）. The sky dimmed（渐渐暗下来）, and the streetlights flickered on（一盏盏亮起） one by one. It dawned on me that...（我忽然明白……） the meaning of life is not always far away; it often lies hidden in（藏在） those inconspicuous（不起眼的） everyday moments. What we need, perhaps, is just to linger（驻足） for a moment and reexamine（重新打量） the world around us.

初始设置

安装后先进入设置页，不先改网页。先填基础信息，再做一组短句互译，两者一起交给 AI 分析，得到种子熟词表后再进入学习视图。单靠学历和工作经历很难判断真实水平；互译用来校正档位，不是用来推出用户会的每一个词。

学历如初中 / 高中 / 本科 / 研究生
英语等级如中考、高考、四级、六级、雅思、托福，可多选或填无
成绩可选；有则帮助估计档位，没有也能生成
工作使用频率几乎不用 / 偶尔读 / 经常读英文材料
短句互译约 10–12 句；分 5–6 档难度，每档约 2 句；英译中和中译英各半

题库预置在扩展内，短句即可，不现场让模型出题。评分看意思是否到位，不按「信雅达」扣分。生成结果是种子：功能词和高频词仍由打包词表托底。用户之后可用难度调节；生成失败或跳过测验时退回「画像 + 托底词表」，设置页可重做。

03

明确不做

这些项已经讨论过，v1 故意排除。

当前结论

v1 不做视频、多语种、划词翻译、全文润色、旧代码迁移。初始设置包含短句互译，但不宣称测完就知道用户的全部词汇。

主要依据

产品方已逐项确认后置或放弃。旧公开产品里，这些能力会拖慢首体验或让选词失控。

适用边界

若原型证明学习视图经常读不完，再启动划词，而不是先做全文中文。

下一步

评审或开发中出现这些需求，先对照本章，默认拒绝进 v1。

视频用量少，已停做
划词翻译解决学习视图局部看不懂，后做
全文润色会改写已打标的词，破坏词表控制
多语种不是加一个列表；词表和分词都会分叉
长篇入学考试不做几十题或现场出题；短句互译控制在十几句
Firefox / Safari / iOS第一版只做 Chrome
04

技术方案

Chrome MV3 扩展 + 确定流水线 + DeepSeek 翻译步骤。

当前结论

两个 Agent 职责分开：设置页根据画像和互译答卷选档生成种子熟词表；阅读时 Translation Agent 只给已切好单位做中文释义。页面上谁是熟词，仍由代码对照词表决定。

主要依据

DeepSeek 官方 Chat Completions 与 OpenAI 兼容，当前模型 ID 为 deepseek-flash 与 deepseek-v4-pro。JSON Output 可用。思考模式默认开启，翻译应显式关闭，否则等待变长。官方首次调用说明

适用边界

扩展直连 DeepSeek，密钥在用户本机。种子词表会漏掉遗忘词。正文提取在复杂站点上会失败，需可禁用站点。

下一步

先落设置页和词表存储，再打通英文页学习视图。

扩展结构

content script

抽取正文、保存原文快照、渲染学习视图、处理原文切换。不持有 API Key，不直连 DeepSeek。

service worker

Translation Agent：排队、调用 DeepSeek、回写结果。失败时保留原文可恢复。

popup / options

填写 DeepSeek Key、初始设置（画像 + 短句互译）、难度、当前站开关。Key 与词表存 chrome.storage.local。

lexicon

打包功能词和课标/词频档。AI 只决定覆盖哪些档，并允许少量补充词；代码合并成个人种子表。

DeepSeek 用法

Base URL：https://api.deepseek.com。v1 默认模型：deepseek-flash。翻译请求关闭思考：thinking: { type: "disabled" } 或 reasoning_effort: "none"。需要结构化生词表时使用 response_format: { type: "json_object" }，并在提示词里要求 JSON，避免空输出或死循环空白。JSON 模式说明

三次模型职责分开：设置页根据画像和互译答卷选择词表档位；中文页段落英译；已确定的生词/短语出中文释义。互译题本身预置，不让模型现场出题。不要一次让模型同时改写全文并决定熟词。

初始熟词表怎么生成

不要求模型从零默写用户会的每一个词。设置页把学历、等级、成绩、工作频率，以及约 10–12 句短句互译答卷一起交给 AI。AI 输出覆盖档位（如初中、高中、大学核心）和可选的少量补充词；代码把对应打包词表与功能词、高频词合并，写入本地熟词表。这是种子，阅读时仍用代码匹配。

互译只校正档位。十几句测不出完整阅读词表，也不能推翻功能词托底。答卷与画像冲突时，以答卷下调档位，不以画像硬抬档位。

短句互译题库

题库打包进扩展，固定题面，避免每次安装难度漂移。短句、日常语境即可，不考长难句翻译课。英译中主要看读懂没有；中译英看意思对不对，不扣文采。

规模约 10–12 题；5–6 档难度，每档约 2 题
方向每档一题英译中、一题中译英
档位建议小学 / 初中 / 高中 / 四级 / 六级 / 专业或学术，实现时可微调命名
评分AI 按档给对错或半对；输出仍是覆盖档位，不是逐词清单

翻译 Agent Prompt 规则

下列规则写入翻译步骤的 system prompt。输入是已切好的英文单位和所在句子；输出只允许该单位的中文释义。

只覆盖本单位括号里的中文必须且仅解释紧挨其前的英文单位，不解释前后词
释义可独立读拿掉英文后，中文应是完整词义或完整短语意义，不是更大句子里剪下来的残片
不改边界不扩大、不缩小给定 span，不把对比、否定、并列的另一半塞进这个单位
不改写页面不输出整句混排，不改英文原文
查看可写入代码的 Prompt 条文 
你只为给定英文单位提供简短中文释义。单位由调用方指定。
- 释义必须且仅覆盖该单位。
- 释义本身应能独立理解，对应完整词义或完整短语意义。
- 不要把该单位之外的句法成分写进释义。
- 不要翻译整句，不要改英文，不要增删单位边界。
输出 JSON：{"items":[{"span":"...","gloss":"..."}]}
gloss 不含括号、不含英文。

词表规则

功能词和最高频约 2000 词默认熟词，任何难度下都不当生词。难度只移动门槛之上的词：更易则更多单位带 （中文）；更难则更多词保持纯英文。匹配用分词加词形还原，不把 This 和 this 当成两种词。

渲染规则

主文本始终是英文；中文只出现在括号里，不替换英文
括号全角 （），紧跟标注单位，中间不插空格
单位可以是词或短语，如 eased、regardless of、It dawned on me that
密度默认稀疏：大部分句子无括号，只标看不懂的单位

短语切分仍是待验证假设。v1 先用词表加常见多词表达（MWE）合并相邻单位，再把整段单位交给 DeepSeek 出一条中文释义。不要让模型自己决定哪些词该标。

05

技术取舍

这些选择应进入以后的编码上下文，而不是再争论产品口号。

当前结论

选确定流水线；页面熟词用代码匹配种子词表；翻译释义只覆盖给定单位；初始熟词表由画像加短句互译映射到打包词表，不让模型从零默写全表，也不让十几句测出全部词汇；选直连 DeepSeek；选 DOM 快照回原文。

主要依据

常见词误判来自把选词交给模型。原文已被定义为处理前页面，本机快照即可。v1 没有账号体系，后端会额外增加范围。

适用边界

若密钥不能放在客户端，或需要统一计费，再引入后端。那会重开安全与架构。

下一步

编码时遇到「让模型更聪明一点」的冲动，先对照本表被否决的方案。

06

开发计划

按可演示切片推进，每期都要能回原文。

当前结论

先做扩展骨架，再做初始设置和种子词表，再做英文页学习视图，再做中文页英译，最后做难度。不要在学习视图可用前接入润色或划词。

主要依据

没有种子词表，英文页会把常见词标成生词。英文页不依赖「先译成英文」，能更早验证渲染。

适用边界

没有排工时。人员与每日可用时间未知。下列分期是依赖顺序，不是日历。

下一步

从第 0 期开始建 Chrome MV3 仓库，跑通加载扩展、保存 Key、打开初始设置页。

分期目标与完成标准
期 做完什么 完成标准
0 骨架 MV3、popup、Key 存储、正文抽取、原文快照 能加载扩展；开关后页面可恢复到处理前
1 初始设置 采集基础信息；预置短句互译；AI 选档并合并打包词表 完成后有一份本地种子熟词表；失败或跳过测验可退回托底表
2 英文页 语种检测、词表打标、DeepSeek 译生词、学习视图 对齐英文样例；this 无括号；可回原文
3 中文页 段落英译后再走第 2 期同一套打标 对齐中文页学习视图样例；回原文仍是中文
4 难度 三档门槛，只移动熟词边界 调档后中英文比例变化，句子不被改写
后置 划词翻译、润色、多语种 v1 验收通过后再开

每期都要守住的约束

  • 模型失败时，用户仍能看到原文或回到原文。
  • 不处理导航、侧栏、未展开区域；只改正文。
  • 不把 API Key 打进内容页或远程日志。
07

验收与回看

没有原型结果之前，不把方案写成已经有效。

当前结论

v1 通过的最低标准是：初始设置能生成种子词表、英文页学习视图可读、常见词不被当生词、原文可恢复。未通过就不要扩功能。

主要依据

这些标准直接对应本轮已锁判断，不依赖未做的划词和润色。

适用边界

尚未有测试数据。站点兼容性失败只能证明该站需禁用，不能单独推翻产品契约。

下一步
